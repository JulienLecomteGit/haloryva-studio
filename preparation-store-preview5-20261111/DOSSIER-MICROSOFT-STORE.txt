COÛT ET SIGNATURE — VOIE RETENUE
Microsoft décrit une nouvelle inscription développeur sans frais via
storedeveloper.microsoft.com. Le type de compte doit correspondre à l'activité :
personnel pour un projet personnel admissible, entreprise si l'activité l'exige.
L'état du compte utilisateur n'a pas été consulté.
Source : https://learn.microsoft.com/en-us/windows/apps/publish/partner-center/open-a-developer-account

Le Store signe les MSIX/AppX après certification ; pas d'achat de certificat
pour cette voie. Il ne signe pas un EXE/MSI hébergé sur GitHub. La distribution
MSIX hors Store exige sa propre signature. Prévoir à terme un lien GitHub vers
le Store pour l'installation simple ; aucune promesse de signature de 2.7.0.
Source : https://learn.microsoft.com/en-us/windows/apps/publish/publish-your-app/package-version-numbering

IDENTITÉ DU PAQUET
Reporter les valeurs exactes de Partner Center dans identite-store.a-renseigner.json :
Package/Identity/Name, Publisher, PublisherDisplayName, nom réservé, ProductId.
Le fichier contient des null explicites tant que ces données sont inconnues.
Ne pas réutiliser HaloryvaStudio.Preview5UnsignedTest ni son Publisher avec OID
d'installation non signée. Le paquet de test ne doit pas être soumis comme produit.
Proposition pour une première version finale : 2.7.1.0 si la version produit
reste 2.7.1 et si l'identité finale n'a pas déjà reçu cette version. À confirmer
avec l'historique Partner Center ; aucune version finale imposée aujourd'hui.
Le nom, l'architecture, les OS et les langues devront correspondre à la réalité
testée. Ne pas déclarer EN/ES tant que l'application ne les fournit pas.

PRÉREQUIS AVANT SOUMISSION
- Compte actif et nom réservé ; identités définitives renseignées.
- Décision sur les langues intégrées à la version finale.
- Traitement/validation du démarrage automatique du paquet ; migration et
  mise à jour selon la portée annoncée ; voir bilan pour les limites connues.
- URL accessible de confidentialité et moyen de support ; textes approuvés.
  Une politique est nécessaire pour les produits Win32/Desktop Bridge.
  Source : https://learn.microsoft.com/en-us/windows/apps/publish/store-policies
- Fiche exacte, captures réelles, droits des ressources et questionnaire IARC.
- Paquet final distinct, contrôlé avec le Windows App Certification Kit (WACK).
- Justification runFullTrust et examen de certification Microsoft.
  MakeAppx valide la structure ; il ne remplace ni WACK ni la certification.
  Source : https://learn.microsoft.com/en-us/windows/apps/publish/publish-your-app/msix/create-app-submission

ACTIONS QUE CETTE PRÉPARATION N'A PAS FAITES
Création de compte, connexion, vérification d'identité, réservation, modification
de droits, validation IARC, fabrication finale, WACK, signature, soumission,
publication ou installation. Ces états restent « à faire », pas « réussis ».
